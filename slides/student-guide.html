Langfuse 실습 폴더로 이동합니다.

“폴더가 없습니다” 또는 코드가 아직 없다면
  1. 아래 버튼으로 실습 ZIP을 노트북에 내려받습니다. ZIP 안에는 airforce-langfuse-student 폴더가 있습니다.
  2. Codespaces 왼쪽 파일 탐색기에 ZIP을 드래그하여 앞 강의 저장소의 최상위 폴더에 업로드합니다. 파일 이름은 airforce-langfuse-student.zip을 유지합니다.
  3. 업로드한 ZIP이 있는 폴더의 터미널에서 아래 압축 해제 명령을 실행합니다.

  1. 위의 cd /workspaces/airforce-langfuse-student 명령으로 이동합니다.
  2. 파일을 편집할 때는 VS Code 메뉴 File → Open Folder…에서 이 경로를 열면 편합니다. 같은 Codespace 안의 폴더만 바뀝니다.

03

GitHub 설정 · 키 등록

받은 키를 Codespaces Secrets에 넣습니다.

키는 강사가 별도로 전달합니다. 이 안내서에는 실제 키가 없으며, 아래 학습 메모에도 키를 적지 않습니다.

  1. GitHub 프로필 → Settings → Codespaces → Codespaces secrets → New secret으로 이동합니다.
  2. 아래 이름으로 값을 등록합니다.
  3. Repository access에서 지금 Codespace가 연결된 저장소를 허용합니다. 앞 강의 환경은 doongsilee/agentic-ai-lecture, 우리 공개 저장소에서 새로 시작했다면 hellojintae/airforce-langfuse-student입니다. 본인 fork로 시작했다면 그 저장소를 선택합니다.
  4. 등록 후 Codespaces 목록에서 해당 환경을 Stop → 다시 열기 합니다. 브라우저 새로고침만으로는 새 키 적용을 확인할 수 없습니다.
Secret 이름넣을 값
LANGFUSE_PUBLIC_KEY배정받은 조 프로젝트의 Public Key
LANGFUSE_SECRET_KEY같은 프로젝트에서 발급한 Secret Key
OPENROUTER_API_KEY강사가 제공한 외부 모델 호출 키

앞 강의에서 같은 모델 키를 LLM_API_KEY로 등록했다면 그대로 재사용할 수 있습니다. 실제 사용 우선순위는 MODEL_API_KEY → LLM_API_KEY → OPENROUTER_API_KEY입니다. 이전 값이 다른 키를 가리키면 담당자와 맞춥니다. GitHub Actions secrets와 Codespaces secrets는 다른 설정입니다.

04

Codespaces · 파일 편집

.env의 일반 설정을 맞춥니다.

저장소 최상위의 .env를 열어 아래 항목을 바꾸고 저장합니다. 아래 블록은 터미널 명령이 아니라 파일 내용입니다. 키는 위 Secrets에서 제공하므로 여기에 붙이지 않습니다.

파일 편집 · 2-C 폴더의 .env 일반 설정
LANGFUSE_BASE_URL=https://jp.cloud.langfuse.com
TRACE_ENABLED=true
LANGFUSE_TRACING_ENVIRONMENT=training
LANGFUSE_RELEASE=2c-20261030

LLM_MODE=cloud
LLM_BASE_URL=https://openrouter.ai/api/v1
LLM_MODEL=openai/gpt-4.1-mini
LLM_TIMEOUT_SEC=30
RUN_TIMEOUT_SEC=180

모델 이름은 현재 교안의 예시입니다. 당일 강사가 지정한 모델이 다르면 그 값을 사용하세요. MODEL_BASE_URL·MODEL_A에 이전 값이 있으면 각각 LLM_BASE_URL·LLM_MODEL보다 우선하므로 확인합니다. 이번 학생 실습에 MODEL_B·JUDGE_MODEL 설정은 필수가 아닙니다.

이제 터미널에서 아래 명령으로 실제 적용된 설정을 확인합니다.

Codespaces 터미널 · 값 대신 설정 유무만 출력
cd /workspaces/airforce-langfuse-student
node --input-type=module -e "import 'dotenv/config'; for (const k of ['LANGFUSE_PUBLIC_KEY','LANGFUSE_SECRET_KEY']) console.log(k, process.env[k] ? 'SET' : 'MISSING'); console.log('MODEL_KEY_EFFECTIVE', (process.env.MODEL_API_KEY || process.env.LLM_API_KEY || process.env.OPENROUTER_API_KEY) ? 'SET' : 'MISSING'); console.log('LANGFUSE_BASE_URL', process.env.LANGFUSE_BASE_URL); console.log('TRACE_ENABLED', process.env.TRACE_ENABLED); console.log('MODEL_BASE_EFFECTIVE', process.env.MODEL_BASE_URL || process.env.LLM_BASE_URL); console.log('MODEL_EFFECTIVE', process.env.MODEL_A || process.env.LLM_MODEL);"
cd lab
확인할 결과

키 관련 항목은 SET, Langfuse 주소는 https://jp.cloud.langfuse.com, 추적은 true, 모델 주소와 모델명은 강사 안내와 같아야 합니다. 이 명령은 키 값 자체를 출력하지 않습니다.

.env를 바꿨는데 다른 값이 보이면

Codespaces Secrets나 기존 환경변수에 같은 이름이 있으면 이 코드에서는 .env보다 우선합니다. 앞 강의 설정과 2-C 설정을 담당자와 대조하고 필요한 설정을 맞춘 뒤 Codespace를 다시 시작합니다. 모든 환경변수나 키를 한꺼번에 출력하지 마세요.
