## 실습 준비

1. 인터넷이 연결된 노트북과 Chrome을 준비합니다.
2. 초대받은 이메일로 [Langfuse Japan](https://jp.cloud.langfuse.com)에 로그인하거나 가입하고, 교육 조직 초대를 수락합니다.
3. `airfoce-lecture` 조직 → `aistudy-assistant` 프로젝트를 엽니다. 학생 역할은 **Viewer(읽기 전용)**입니다.
4. [AI Study 교육 페이지](https://aistudy.my/airforce)를 열고 강사 안내에 따라 도우미에 접속합니다. 같은 브라우저를 계속 사용하세요.

학생 API 키, 모델 키, Codespaces, 로컬 개발환경 설치는 필요하지 않습니다. 접속이 안 되면 초대 이메일과 선택한 조직·프로젝트부터 확인하고 강사에게 알려 주세요.

## 진행 순서

| 순서 | 할 일 | 남길 결과 |
|---|---|---|
| 1 | 질문①을 한 번 보내고 **내 로그 보기**를 엽니다. | Q1의 Trace URL·질문·답변 |
| 2 | 같은 Q1에서 root → 검사 → 검색 → 생성·검증 → 결과를 읽습니다. | 경로·근거·시간·토큰·모델 비용 |
| 3 | 질문②·③·④는 각 장표에서 한 번씩 보내고 실제 경로를 적습니다. | Q2~Q4의 Trace URL·경로·이유 |
| 4 | Q1과 Q4를 두 탭으로 놓고 비교합니다. | 생성 수·시간·모델 비용 차이 |
| 5 | Q1로 돌아와 실제 Prompt 버전과 Score의 Source·타입·값을 읽습니다. | 점수의 의미와 한계 |
| 6 | 관찰표 네 줄과 비교 한 문장을 저장합니다. | 관찰 사실 + 추가로 확인할 것 |

장표 하단에 **지금 할 행동**이 나옵니다. Q1을 설명하는 동안 새 질문을 보내지 않습니다. 기본4회, 선택 반복1회입니다. 예상 경로와 달라도 실제 값을 적고, 비어 있는 값은 `0` 대신 `미표시`로 남깁니다. 접속이 안 되면 강사 예시로 진행하고 관찰표에 표시하세요.

**66장 질문표와 각 실습 장표에 강사 예시 Trace ID·바로가기**가 표시됩니다. ID를 누르면 해당 기록이 열립니다(Langfuse 로그인·프로젝트 조회 권한 필요). 학생이 새로 보낸 질문의 ID는 다르므로 자신의 기록은 **내 로그 보기**로 여세요. 시간·토큰·비용 장표의 B는 별도 캡처 기록이며, 다른 예시의 수치와 섞지 않습니다.

교안 답변, 웹 검색 안내, 문의 안내, 차단 응답을 관찰합니다. 웹 검색 안내는 자동 검색 실행을 뜻하지 않습니다. 점수는 앱의 처리 결과 분류인지, 형식 검사인지 구분해서 읽습니다.

## 요청별 관찰표

| 항목 | 적을 내용 |
|---|---|
| 질문·Trace ID | 어떤 요청을 읽었는가 |
| 응답 유형·근거 | 어떻게 처리됐으며 어떤 기록으로 확인했는가 |
| 시간 | 전체 요청과 모델 호출 각각의 지연, 단위 |
| 토큰·모델 비용 | 입력/출력 사용량과 기록된 모델 비용 |
| 프롬프트 | 실제 사용한 이름·버전, 연결이 없는 경우의 정보 |
| Score | 이름·Source·값·Comment, 확인할 수 있는 범위 |
| 비교 | 다른 요청과 무엇이 달랐고 그 이유를 어디서 찾았는가 |

모두 같은 프로젝트를 조회하므로 다른 학생의 기록도 보입니다. User ID 필터는 내 기록을 찾는 기능이며 접근 권한을 분리하지 않습니다. 실습 질문에는 개인정보나 비밀값을 넣지 마세요.
